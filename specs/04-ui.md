# UI Specification

## Goals

- Fast, modern, responsive desktop UI
- Dark theme by default
- Strong fan curve editing experience
- System tray support

## Technology decision (locked for v1)

| Option | Pros | Cons |
|--------|------|------|
| **egui + eframe** ✅ | Pure Rust, fast iteration, immediate mode, excellent for tools | Less “native” OS chrome |
| iced | Declarative, polished | Heavier migration cost now |

**Decision**: **egui + eframe**. Workspace pins **`egui` / `eframe` 0.35** (root `Cargo.toml`).  
App trait: `eframe::App::logic` + `App::ui` (egui 0.35 panel API: `egui::Panel::top/right/bottom`, `CentralPanel`).

## Main screens (product map)

1. **Dashboard / Controls** — combined live view + sliders  
2. **Curve editor panel** — profiles + curve assignment + Apply now  
3. **Options** — graph visibility, host sensors, hide 0 RPM, curve auto checkbox (synced with header), language picker  
4. **Settings future** — startup  

## System tray

- `tray-icon` crate (Windows target); built inside the eframe app-creation closure, after the event loop has started
- Closing the main window minimizes to tray instead of exiting (`ViewportCommand::CancelClose` + `Visible(false)`); tray "Exit" is the only path that actually terminates
- Icon state (normal / warning / error) driven by poll/write errors and PawnIO availability
- Quick menu: open window, apply default profile now, exit
- If the tray fails to initialize (rare), minimize-to-tray is disabled so the window is never left unreachable

## UX / safety rules

- Critical write path always gated; clear **READ-ONLY** vs **WRITE ENABLED** banner
- No silent elevation / no auto-install of PawnIO
- Prefer non-blocking UI (poll + write queue)
- Avoid unnecessary process spawns that trip AV heuristics (no PowerShell for storage; fixed `nvidia-smi` paths)
