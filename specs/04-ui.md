# UI Specification

## Goals

- Fast, modern, responsive desktop UI
- Dark theme by default
- Excellent fan curve editing experience
- System tray support

## Technology decision (locked)

| Option | Pros | Cons |
|--------|------|------|
| **egui + eframe** ✅ | Pure Rust, very fast iteration, immediate mode, excellent for tools | Less "native" look |
| **iced** | More declarative, good looking, growing ecosystem | Slightly heavier |

**Decision (Phase 0)**: **egui + eframe**. Locked for v1 to maximize iteration speed.
Workspace deps are declared in the root `Cargo.toml` (`egui` / `eframe` 0.29).
Can be revisited only with an explicit spec update.

## MVP status (Phase 2 partial)

Shipped: single dark window with live temps / RPM / duty **sliders**, channel display names, poll worker thread.
Launch: `cargo run -- ui` (flags: `--hw-only`, `--allow-hw-write`, `--no-hw`).
Hardware sliders locked unless `--allow-hw-write`. Labels from `channel-map.json` (`map-init`).

## Main screens

1. **Dashboard** ✅ MVP (combined with controls)
   - Overview of all temperatures and fan speeds
   - Backend / read-only banner

2. **Controls** ✅ MVP
   - List of active controllable fans
   - Manual duty slider + current RPM
   - Write gated by `--allow-hw-write`

3. **Curve Editor** (later)
   - Visual editor with draggable points
   - X = temperature (°C), Y = duty (%)
   - Live preview

4. **Profiles** (later)
   - List, create, rename, delete, apply

5. **Settings** (later)
   - Backend status (PawnIO)
   - Theme, language, startup behavior
   - Plugin management

## System tray

- Icon with color indication (normal / warning / error)
- Quick menu: apply profile, exit, open main window

## Accessibility & UX notes

- All critical actions must be reachable without hunting
- Clear feedback when a control cannot be written
- No modal dialogs for normal operations
